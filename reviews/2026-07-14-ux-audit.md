# Musializer UX Audit — 2026-07-14

Code-level review of `feature/scene-engine-foundation`, covering interaction
flow, error/feedback quality, visual polish, and per-scene tuning depth.

**Method:** four parallel Sonnet 5 sub-agents did independent, read-only
source review — no code was modified and no runtime screenshots were taken.
~10,300 LOC surveyed across `src/plug.c` and the seven scene modules. Line
numbers reflect the branch at review time and may drift with further edits.

**Totals:** 34 UX findings (12 high / 15 medium / 7 low) plus a tunability
comparison across all 7 scenes.

## Fix these five first

1. **Scene grid can render zero buttons.** At the app's own documented 640px
   minimum height with Lyrics or Export open, `scene_browser()` silently
   returns before drawing anything (`plug.c:4501`) — a user loses the only
   way to change scenes, with no error, no scrollbar, nothing.
2. **Error toasts are cut off mid-word**, exactly as seen in the reported
   screenshot — `notice_tray()` clips `detail`/`path` text in a fixed
   single-line scissor box (`plug.c:4784-4834`) instead of wrapping, and
   offers only "Dismiss," never retry or copy-log.
3. **The accent color means four different things at once** — selected,
   active job, primary action, and "about to destroy data" all share
   `COLOR_ACCENT`, so Delete looks exactly like Save.
4. **Opening "Tune" silently resizes the OS window** with no opt-out
   (`plug.c:4143`) — surprising for anyone who's positioned the window
   deliberately (e.g. for a capture region).
5. **Three scenes are visibly under-tunable** for their rendering
   complexity — Spectral Terrarium is 382 lines of ecosystem simulation
   behind only 3 sliders, one of which (camera motion) doesn't actually
   drive the simulation clock at all.

## 1. Interaction & Flow (9 findings)

Discoverability, state-transition friction, keyboard shortcuts, and what
happens when the window gets small. Sourced from `plug.c`,
`scene_settings.c`, and the README's documented golden path.

### HIGH

**1.1 Scene selector can render nothing at the app's own supported minimum size**
`plug.c:4501`

```c
scene_browser(): if (row_height < 30.0f) return;
scene_panel_height = fminf(292.0f, fmaxf(0.0f, sidebar_height - 120.0f));  // plug.c:5677
SetWindowMinSize(960, 640);  // musializer.c:157
```

At h=640 with Lyrics or Export open, `timeline_height` grows to 330
(`plug.c:5648-5653`), squeezing the scene panel until `row_height` drops
below 30 and the whole scene grid — including the Tune toggle — draws
nothing. No greying-out, no scroll, no message.

*Fix:* make the scene grid scroll like the tracks panel already does, or
clamp `row_height` to a usable floor and let the panel scroll instead of
the buttons vanishing.

**1.2 Opening "Tune" silently resizes/repositions the OS window**
`plug.c:4143`

`set_scene_settings_open()` calls `SetWindowSize(p->scene_settings_expanded_width, GetScreenHeight())`,
gated by `scene_settings_window_can_expand()` (`scene_settings.c:434`), and
reverts on close (`plug.c:4153`). No setting or modifier suppresses it.

A user who manually positioned the window (e.g. for an OBS capture region,
or snapped beside another app) has it silently grow ~340px from a
plain-looking toggle labeled "Tune" — nothing hints the OS window itself
will move.

*Fix:* auto-expand once per session, or gate behind a visible "expand
window" affordance / persisted opt-out.

**1.3 Scene shortcuts 1–7 have zero on-screen affordance**
`plug.c:1007-1025`

Scene grid buttons draw only `scene_name(id)` (`plug.c:4512`) with no hint,
while every icon-only transport control already surfaces its shortcut via
the existing `tooltip()` helper — "Render [R]" (4893), "Play [SPACE]"
(4861), "Mute [M]" (4766), "Collapse [F]" (4604).

The README's fastest documented interaction ("keys 1–7 switch scenes") is
invisible in the running app; a user who never opens the README never
finds it, while icon buttons a few pixels away teach their own shortcuts
for free.

*Fix:* reuse the existing tooltip pattern on the scene grid:
`tooltip(row, "[1]", ...)`.

### MEDIUM

**1.4 Browsing scenes to compare them is indistinguishable from committing, and autosaves in ~1.5s**
`plug.c:3809-3816`

Both the rail click (4514-4518) and the keyboard shortcut (1018-1024) call
`mark_project_dirty()` immediately; `poll_project_autosave()` commits once
`GetTime() - dirty_since >= 1.5`. There's no "preview" state — clicking
through scenes to compare looks writes the track's base scene to disk
within ~1.5 seconds, with nothing confirming a click was a look rather
than a commit.

*Fix:* push a lightweight notice ("Base scene set to X") so the commit
becomes visible, matching feedback already given for other state changes.

**1.5 +Feel / +Scene / +Custom look identical but have very different consequences**
`plug.c:2296-2337`

Same button chrome, differentiated only by a 0.8-alpha outline color.
`+Scene` captures a full settings snapshot with export-time consequences
(`record_scene_cue()`); `+Feel`/`+Custom` just drop a single-value marker.
No tooltip on any of the three.

*Fix:* one-line tooltip per button stating what it records, using the
helper already in use elsewhere.

**1.6 Scene "Reset" has no confirm or undo, unlike the app's own pattern for similarly risky actions**
`plug.c:4256-4262`

Reset fires `scene_settings_reset_scene()` on one click. Compare "Clear
manual" events, which requires an explicit "Confirm clear" second click
and keeps a one-shot `event_undo` buffer for an "Undo clear" button
(2341-2372). Hand-tuned sliders vanish in one misclick, while a comparably
destructive action got a two-step confirm-and-undo treatment.

*Fix:* apply the same arm/confirm(/undo) pattern already built for Clear
manual to Reset.

**1.7 At minimum window width, the inspector leaves almost no room for the actual preview**
`scene_settings.c:408-431`

At the enforced 640px minimum with the inspector open, `inspector_width`
and `tracks_width` both clamp to their 240px floors, leaving roughly 160px
for the visualizer preview itself — the one thing the whole app exists to
show, at a size the app advertises as supported.

*Fix:* auto-collapse the tracks rail when combined chrome would leave less
than ~30% of the window for preview.

### LOW

**1.8 Adjacent Load / Update / Delete preset buttons have no distinguishing tooltip**
`plug.c:4318-4358` — Delete sits directly beside Update at identical size;
a slightly mis-aimed click destroys a preset instead of replacing it.
*Fix:* tooltip on Delete at minimum ("Removes the selected preset").

**1.9 Three overlapping seek mechanisms compete for the same compact strip**
`plug.c:2393-2416` — seek buttons at 1s/0.1s/10s, an inline modifier-key
hint, and waveform click-drag all exist for the same action. *Fix:*
consider dropping the explicit 0.1s/10s buttons now that the modifier hint
is shown inline, reclaiming horizontal space for the waveform.

## 2. Feedback & Errors (13 findings)

Whether notices, toasts, and the Assist panel actually tell a user what
happened and what to do next. Sourced from `ui_notice.c/.h`,
`assist_ui_state.c`, and every `notice_push` call site in `plug.c`.

### HIGH

**2.1 Toast text is scissor-clipped mid-word — the exact bug in the reported screenshot**
`plug.c:4784-4834`

`notice_tray()` draws `detail` and `path` as single-line `DrawTextEx`
calls inside a `BeginScissorMode` box sized `card.width - 102` (~258px at
15pt). The real string pushed at 3117-3119 — "The helper exited before
producing a validated result." — is simply cut off wherever it hits the
clip edge; the log path clips the same way.

*Fix:* wrap detail/path across the card's already-reserved 2-line height,
or truncate with an ellipsis plus a way to see the full text.

**2.2 Error toasts offer only "Dismiss" — no retry, no copy/open log**
`plug.c:4822-4832`

One button is drawn for every notice regardless of severity, even though
`ui_notice_is_actionable_failure()` already flags error+path/persistent
notices as special — the flag exists but nothing acts on it. The user must
manually navigate back to Assist, re-arm the mode, and click Start again;
the visible log path is inert text they can't copy or open.

*Fix:* add "Retry" and "Copy path" actions specifically for notices where
`is_actionable_failure()` is true.

**2.3 Every Assist pre-launch failure collapses into one generic, sometimes-wrong message**
`plug.c:2582-2593`

`assist_job_start_failed()` returns only a bool — no reason code — for
mkdir failure, oversized paths, exhausted artifact names, missing helper,
or spawn failure. The caller always pushes "Analysis could not start —
check Python, required model tools, credentials, and the job log." If
mkdir fails before the log path is computed, the toast points at a log
that was never written.

*Fix:* propagate a specific failure reason; only reference the log path
when the file actually exists.

**2.4 Export has no proactive FFmpeg check; Assist does**
`plug.c:4987-5030, 5841-5847`

Assist disables its mode buttons and explains why via
`assist_start_block_reason()`. Export's "Choose output and render" has no
equivalent — failure only surfaces mid-render: "FFmpeg could not start or
stopped before the video was complete." A user loses time picking an
output destination and waiting before learning FFmpeg was never
installed.

*Fix:* mirror Assist's precheck-and-explain pattern for Export.

**2.5 Microphone capture errors bypass the notice system entirely — a known TODO**
`plug.c:5813`

```c
// TODO: report capture device error via the popup mechanism.
```

followed by a hardcoded fullscreen "Capture Device Error: Check the Logs"
with no detail, no path, ESC to dismiss.

*Fix:* route through `notice_push` like every other failure path in the
app.

### MEDIUM

**2.6 Severity has no visual identity beyond a text label**
`plug.c:4772-4810` — the accent bar and "INFO / DONE / WARNING / ERROR"
label always draw in `COLOR_ACCENT`. A blocking error and a routine
success look identical except for one 14pt word. *Fix:* map each severity
to a distinct color, not just a distinct word.

**2.7 In-panel failure status is styled like idle text, contradicting the loud toast above it**
`plug.c:1945-1955` — the status line "Analysis failed | Editor content
unchanged | Log: ..." is colored `active ? signal : COLOR_UI_INK`; since a
failed job isn't "active," it renders in plain ink, identical to the idle
"Ready" state. This is the tiny grey text visible in the reported
screenshot. *Fix:* color status by outcome (failed/succeeded/idle), not by
whether a job happens to be currently running.

**2.8 Toast and panel status describe the same failure in different, uncorrelated words**
`plug.c:3117-3119, 1945-1949` — toast says "The helper exited before
producing a validated result"; the panel says "Analysis failed | Editor
content unchanged | Log: ..." — nothing ties them together, so a user may
read two separate incidents. *Fix:* single source of truth for the detail
text, cross-referenced explicitly between toast and panel.

**2.9 "Armed" and "running" look the same for Assist mode buttons**
`plug.c:1899-1902` — `selected` is true for both
`assist_confirmation_pending` and `active`, so the button gets identical
highlighting whether it's merely armed or genuinely mid-job. Only a small
status line beneath tells them apart. *Fix:* give "armed, waiting for
confirm" a visually distinct state from "job running."

**2.10 Notice queue silently drops beyond 3 visible — no "+N more" indicator**
`ui_notice.c:22-64, plug.c:4791` — the queue holds up to 16 with
priority-based eviction, but the tray only ever shows 3. A still-relevant
persistent error can silently scroll out of view behind newer notices with
no count shown. *Fix:* surface a queue-depth affordance when notices are
hidden.

**2.11 Close-guard dialog bundles up to four unrelated problems into one Yes/No**
`plug.c:5237-5271` — `plug_confirm_close()` concatenates dirty projects,
dirty draft, staged suggestions, and running jobs into one paragraph
inside a single yes/no `tinyfd_messageBox`. Choosing "Cancel" returns to
the app with no indication which item to resolve first. *Fix:*
prioritize/order the message, or offer per-item resolution instead of one
blended prompt.

### LOW

**2.12 Disabled Assist mode buttons have no tooltip explaining why they're blocked**
`plug.c:1248-1268` — *Fix:* attach `assist_start_block_reason()` as a
hover tooltip on each disabled button, same pattern used for transport
controls.

**2.13 Two-step confirmation warnings auto-dismiss in 5s, before the second click happens**
`plug.c:1028-1050, 2099-2101, 2396-2397` — "Confirm staged changes" and
"Confirm manual-event clear" inherit the default 5s duration and can
vanish before the user reads them and clicks Confirm. *Fix:* make notices
that gate a pending two-step action persistent until that action resolves.

### Working well

The local/remote privacy boundary README claims held up under inspection —
`assist_mode_badge()` shows "LOCAL AUDIO" vs. "OPENROUTER AUDIO" under
every mode button at all times, and the confirmation step restates the
workflow and data boundary before "Start analysis" unlocks. Genuine
two-step disclosure, not just documentation.

## 3. Visual Polish (12 findings)

Typography, color semantics, spacing, and empty states. Sourced from
button primitives, panel-drawing code, and the color/font constants in
`plug.c`.

### HIGH

**3.1 A working icon pipeline exists but is used on only 3 of dozens of actions**
`plug.c:183-199, 4842-4930` — `resources/icons/` has 5 PNGs wired via
`UI_ICON_*` and `DrawTexturePro`, but every other control — all 7 scenes,
all preset actions, Open/Save/Save As, Lyrics/Assist/Export/+Feel/+Scene/+Custom
— goes through the plain `text_button()` with no glyph at all. The four
transport icons look like a different, more finished app sitting inside a
text-button shell. *Fix:* either commit fully to text-first (drop the 3
icon buttons) or extend the existing pipeline to Save/Export/scene
selection — the highest-frequency actions.

**3.2 Selected, hover, and disabled states differ only by a flat color swap**
`plug.c:1195-1268` — no scale/press feedback, no shadow or depth anywhere.
The scene-setting slider's hover ring is visually identical whether you're
hovering or actively dragging (4229-4231). A user can't tell "I am
hovering" from "I am actively dragging the value." *Fix:* distinct stroke
width/color for actively-dragged vs. hover; a subtle press/depth cue on
button mouse-down.

**3.3 Destructive and neutral actions are visually identical**
`timeline.c:2369-2400, scene_settings_panel:4336-4344` — "Clear manual"
and "Delete preset" render with the same `text_button` styling as "Load" /
"Save new" / "Update" / "Save As" — the only change on a confirm-state is
`selected=true`, which paints it the same accent blue used for "selected
scene" everywhere else. `COLOR_ACCENT` simultaneously means "selected,"
"active job," "primary CTA," and "you are about to destroy data." *Fix:*
add a dedicated danger color, used only for Delete / Clear-confirm states,
distinct from the accent.

**3.4 No coherent type scale — 15+ distinct font sizes used ad hoc**
`plug.c`, `DrawTextEx` call sites — sizes 12, 13, 14, 15, 16, 17, 18, 19,
22, 24, 28, 34, 38, 84 all appear as raw float literals with no named
constants. The Assist panel's section header uses 19.0f while Scene
Settings' conceptually similar label uses 15.0f. *Fix:* named constants —
`UI_FONT_HEADER / LABEL / CAPTION / VALUE` — and normalize call sites onto
them.

### MEDIUM

**3.5 Panel padding/gap constants drift between 8, 10, and 18px across adjacent panels**
`plug.c:4463, 1839-1840, 2125-2126, 4246, 2316` — stacked panels' left-edge
content inset visibly jumps by 2x between neighbors. *Fix:* one
`UI_PANEL_PADDING` and `UI_CONTROL_GAP` constant, reused everywhere.

**3.6 Control heights are inconsistent across panels (24–38px, no shared constant)**
`plug.c`: multiple panel functions — 36px assist/export buttons, 30px
scene-settings buttons, 28px preset nav, 32px transport row, 24px Tune
toggle, up to 38px scene rows. *Fix:* one `UI_BUTTON_HEIGHT = 36.0f`
constant for standalone actions; document exceptions for genuinely compact
controls.

**3.7 Empty states reuse disabled-button chrome instead of a deliberate empty style**
`plug.c:4308-4310, 3908` — "No saved presets" renders via
`disabled_text_button` — the same washed-out look used for any
temporarily-disabled control — sitting between two dead-looking nav
arrows, so the whole presets strip looks broken rather than "nothing here
yet." *Fix:* a distinct empty-state style: dashed border, no button
chrome, one line of muted guidance text ("Save a preset to see it here").

**3.8 Bottom-row category color-coding is a 1px border, invisible at a glance**
`timeline.c:2336-2338` — Lyrics/Assist/Export get an amber outline,
+Feel/+Scene/+Custom get a per-type outline — a real, intentional grouping
decision that doesn't survive down-scaling: at normal viewing distance all
seven buttons read as one undifferentiated row. *Fix:* 2px border and/or a
matching-hue chip inside the button, or differentiate by fill saturation
instead of border alone.

**3.9 Waveform is a single flat-alpha fill with a bare 2px playhead line**
`plug.c:2248-2292` — every column draws at a fixed
`ColorAlpha(COLOR_ACCENT, 0.58f)` regardless of amplitude. The playhead
has no cap, glow, or handle, making it easy to confuse with event markers
of similar visual weight nearby. *Fix:* amplitude-based gradient on the
fill; a distinct playhead cap (triangle or filled circle) to separate it
from event markers.

### LOW

**3.10 Primary actions (Export) get the same visual weight as low-frequency ones (+Custom)**
`timeline.c:2331-2335` — *Fix:* modest size/margin increase for Export
relative to the six same-row buttons.

**3.11 Scene Settings panel doesn't adapt height between 3-control and 10-control scenes**
`plug.c`: `scene_settings_panel`, `row_height=76.0f` — a fixed row height
across a fixed panel height means sparse scenes (Spectrum) leave a large
blank lower region that dense scenes (Atlas) fill and scroll — perceived
"finish" varies by which scene happens to be selected. *Fix:* cap panel
height to `min(fixed_max, setting_count * row_height)` plus footer.

**3.12 The same muted-gray is used for both informational captions and disabled emphasis**
`plug.c`: `COLOR_UI_MUTED` usage — "PRESETS 0/8" (informational) and "No
saved presets" (disabled) render in the same gray, reducing the color's
diagnostic value for "this control is inactive" specifically.

### Working well

The palette itself is fine — `COLOR_ACCENT` / `COLOR_UI_SURFACE` /
`COLOR_UI_MUTED` / `COLOR_UI_RULE` are coherently referenced everywhere.
The problem is applying consistent colors on an inconsistent grid of
sizes, paddings, and heights, plus near-total absence of iconography and
semantic (danger/empty/primary) styling.

## 4. Scene Settings Tunability

How the seven scenes' tunable-parameter counts compare against their
actual rendering complexity, and where headroom exists to extend
`scene_settings.c`.

| Scene | Settings | Source LOC | Assessment | Why |
|---|---|---|---|---|
| Spectrum | 3 | 114 | **Under-tunable** | Three distinct rendering passes (bars, trail-blend bloom, core glow) share hardcoded shader uniforms; only amplitude/trail/saturation are exposed. |
| Pulse Field | 5 | 79 | Adequate | Single-technique ring renderer — scale/rings/motion/arc/weight cover the whole mechanism cleanly. |
| Orbital Lattice | 5 | 521 | Adequate (borderline) | Covers core geometry, but camera framing, damping rates, and ring-wave amplitude stay fixed. |
| ASCII Field | 4 | 425 | Adequate | Each setting drives a genuinely distinct subsystem (drift, glyph animation, CRT bands, chromatic split). |
| Song Atlas | 10 | 660 | **At ceiling** | Already at `SCENE_SETTINGS_MAX_CONTROLS`; every setting, including both toggles, verifiably switches render paths. |
| Spectral Terrarium | 3 | 382 | **Under-tunable** | Full particle/plant/creature ecosystem behind 3 sliders; creature speed, glass opacity, population density all fixed. |
| Constellation | 3 | 318 | **Under-tunable** | Node field + event highlighting behind 3 sliders; event glow duration, spread radius, hue swing all fixed. |

### Capacity constraint before adding anything

`scene_settings_export_mappings()` packs every scene's settings into one
flat array capped by `MUSI_PROJECT_MAX_MAPPINGS_PER_SCENE = 40`
(`project.h:14`, mirrored in `schemas/project-v1.schema.json`'s
`maxItems: 40`). The current total across all 7 scenes is **33**
(`tests/test_scene_settings.c:147`) — about 7 slots of headroom, not the
per-scene cap of 10. Raising `SCENE_SETTINGS_MAX_CONTROLS` or the global
cap touches `Scene_Settings_Snapshot.values[10]`, preset storage, and the
schema together — and needs the same `legacy_atlas`-style backward-compat
branch already present in `scene_settings_snapshot_valid()`
(`scene_settings.c:177-189`) for any scene whose control count changes.

### Spectrum — proposed additions (`scene_spectrum.c`)

| Key | Label | Range | Replaces |
|---|---|---|---|
| `settings.spectrum.glow_softness` | Glow softness | 1.0–8.0, def 3.0 | `3.0f` / `5.0f` — L49, L89 |
| `settings.spectrum.hue_swing` | Hue swing (deg) | 0–120, def 55 | `55.0f` — L24 |
| `settings.spectrum.core_glow` | Core glow size | 0.0–3.0, def 1.0 | decouples from Trail — L99 |
| `settings.spectrum.bar_taper` | Bar taper | 0.3–1.5, def 0.5 | `sqrtf(t)` exponent — L42 |

### Spectral Terrarium — proposed additions (`scene_spectral_terrarium.c`)

Note: the existing "Camera motion" setting is only weakly connected — it
drives hue rotation and camera orbit but never reaches the simulation
clock (particle drift, creature movement always run at a fixed real-time
rate regardless of the slider).

| Key | Label | Range | Replaces |
|---|---|---|---|
| `settings.terrarium.sim_speed` | Ecosystem motion speed | 0.2–2.5, def 1.0 | new: scale the sim clock itself |
| `settings.terrarium.creature_speed` | Creature speed | 0.2–2.0, def 1.0 | fixed base range — L135 |
| `settings.terrarium.glass_opacity` | Habitat glass opacity | 0.0–0.4, def 0.13 | `0.13f` alpha — L293 |
| `settings.terrarium.density` | Population density | 0.3–1.0, def 1.0 | subsample fixed-capacity arrays, Atlas-detail pattern |

### Constellation — proposed additions (`scene_constellation.c`)

| Key | Label | Range | Replaces |
|---|---|---|---|
| `settings.constellation.event_duration` | Event glow duration (s) | 0.5–5.0, def 2.4 | `age > 2.4` cutoff — L96 |
| `settings.constellation.event_reach` | Event spread (nodes) | 1–6, def 2 | fixed neighbor gate — L100 |
| `settings.constellation.hue_swing` | Hue swing (deg) | 0–140, def 70 | `70.0f` — L141 |
| `settings.constellation.density` | Star density | 1–3, def 1 | stride through fixed 72-node array — L12 |

### Spot-checked and clean

Every Orbital Lattice and Song Atlas setting — including both Atlas
toggles — was traced to genuinely visible geometry, color, or camera
changes. No dead settings found in either scene.
